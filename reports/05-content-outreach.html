Content Systems Overview

Blog (Manual)
Editor-driven post creation with AI assistance
  • Rich text editor with Claude Haiku autocomplete suggestions
  • SEO meta fields: title, description, canonical, og:image
  • Draft / Published / Scheduled status workflow
  • Category and tag taxonomy system
  • Slug auto-generation with manual override
Autoblog
RSS-fed automated content pipeline
  • User configures RSS feed sources per brand/topic
  • Cron fetches feeds, deduplicates, queues new items
  • LLM detector filters AI-generated source content
  • Claude Sonnet rewrites / summarises into original posts
  • Posts published to /blog with auto-SEO metadata
PMB (Press & Media Blast)
Scheduled press release and media outreach
  • User creates press release draft in rich editor
  • Weekly and monthly scheduled distribution
  • Email delivery via Resend to media contact lists
  • Open rate tracking per recipient per blast
  • Monthly performance digest auto-generated
AOE (AI Outreach Engine)
Automated prospect discovery-to-email funnel
  • User defines target audience + outreach goal
  • Claude discovers relevant domains / contacts
  • Personalised email drafted per prospect via Claude Haiku
  • Email sequencing: initial + 2 follow-ups spaced by days
  • Reply detection + campaign pause on positive response

Issues Found

Critical Autoblog Cron Has No Circuit Breaker — Infinite Retry on Claude API Errors

When Claude API returns an error during post generation, the failed queue item is never marked as failed — it remains in the queue and the cron attempts it again on the next 6-hour cycle. If Claude is degraded for 12 hours, the same 50 items are retried 2+ times each. There is no dead-letter queue, no failure counter, and no retry limit. This wastes API quota and can cause infinite loops.

Recommended Fix

Add an attempt_count column to the autoblog_queue table. Increment on each attempt. After 3 failed attempts, mark status as 'failed' and stop retrying. Log the failure reason. Surface failed items in the admin panel. Add a dead-letter view so editors can manually requeue or dismiss items.

📄 app/api/cron/post-generator/route.ts · lib/db/autoblog-queue.ts
Critical AOE Email Validation Is Regex-Only — Sends to Invalid Addresses

The AOE prospect email validation only checks format (regex match for @ and domain). No MX record lookup is performed, no email deliverability verification, no disposable domain check. Claude-generated prospect emails are frequently guessed patterns (info@domain.com, contact@domain.com) that may not exist. Sending to invalid addresses hurts sender reputation and can cause domain blacklisting.

Recommended Fix

Before sending any AOE email, perform a DNS MX record lookup to verify the domain has mail servers. Integrate a lightweight email verification API (e.g., Abstract API, ZeroBounce) for catch-all detection. Add a disposable domain blocklist. Track bounce rates per campaign and auto-pause campaigns exceeding 10% hard bounces.

📄 lib/services/aoe-discovery.ts · lib/utils/email-validator.ts
High PMB Blast Sends Individual Resend API Calls Per Recipient

The PMB blast runner makes one Resend API call per email recipient. Resend’s free tier rate limit is 2 requests/second and paid tier is 100/second. A media list with 500 contacts will take 5+ seconds and 500 API calls. Resend supports batch send via their /emails/batch endpoint (up to 100 per call) but this is not used.

Recommended Fix

Replace individual Resend calls with the batch endpoint: group recipients into chunks of 100 and call /emails/batch. This reduces 500 API calls to 5 calls, stays well under rate limits, and reduces cron execution time from minutes to seconds. Update pmb_events tracking to handle batch response format.

📄 app/api/cron/pmb-runner/route.ts · lib/services/email.ts
High LLM Detector Uses Fragile Regex Patterns — High False Negative Rate

The Autoblog LLM detector that filters AI-generated source content uses a regex-based approach (looks for phrases like “As an AI language model”, “I cannot”, “certainly!”). Modern AI-generated content from GPT-4o and Claude does not contain these patterns. The detector has a high false negative rate — AI content passes through and gets rewritten into Uptrue posts, creating plagiarism and content quality risks.

Recommended Fix

Replace regex detector with a Claude Haiku classification call: send a short excerpt and ask “Is this likely AI-generated? Respond yes/no with confidence 0-100.” Cache results. Reject content with confidence >70%. This is a single Haiku call (<$0.001) and vastly more accurate than regex patterns against modern LLM outputs.

📄 lib/services/llm-detector.ts
Medium Social Posting Feature Disconnected from Publishing Flow

There is social posting functionality in the codebase (Twitter/X, LinkedIn) but it is not wired into the Autoblog publish flow. When a new post goes live, no social post is created or queued. The feature exists as a standalone manual action only. Users would expect “auto-publish to social” given the blog is already automated.

Recommended Fix

After a successful Autoblog post publish, call lib/services/social-poster.ts with the post title, excerpt, and URL. Make this configurable per user: on/off toggle per social platform in brand settings. Queue social posts via a social_post_queue table to avoid synchronous posting in the publish flow.

📄 lib/services/social-poster.ts · app/api/cron/post-generator/route.ts
Medium AOE Campaign Has No Unsubscribe / Opt-Out Mechanism

Emails sent by the AOE system do not include an unsubscribe link. This is a legal requirement under CAN-SPAM (US), GDPR (EU), and CASL (Canada). Users running AOE campaigns are at risk of regulatory fines and spam complaints. Resend requires commercial emails to include unsubscribe links, and repeated failures to do so will result in account suspension.

Recommended Fix

Add a one-click unsubscribe link to all AOE email templates using Resend’s built-in unsubscribe header support. Store opt-outs in an aoe_unsubscribes table keyed by email address. Before sending any email in any AOE sequence, check this table and skip opted-out addresses. Show opt-out count in campaign analytics.

📄 lib/services/aoe-mailer.ts · app/api/aoe/unsubscribe/route.ts
Medium Autoblog Queue Grows Unbounded — No Pruning or Archival

The autoblog_queue table accumulates all processed, failed, and completed items with no archival or pruning policy. With daily RSS processing across many users, this table will grow to millions of rows over time. Query performance degrades as the table grows and there is no cleanup cron.

Recommended Fix

Add a weekly cron that moves completed queue items older than 30 days to an autoblog_queue_archive table (or deletes them). Create an index on (status, created_at) to keep active-item queries fast regardless of total table size. Log archive counts in the admin panel.

📄 app/api/cron/ · lib/db/autoblog-queue.ts
Low Blog Editor Has No Autosave — Users Lose Work on Navigation

The manual blog editor does not autosave drafts. If a user navigates away or the browser crashes, their work is lost. This is a standard UX expectation for any content editor and has already resulted in user complaints.

Recommended Fix

Add debounced autosave: after 3 seconds of inactivity, silently PATCH /api/posts/[id] with current draft content. Show last-saved timestamp in editor toolbar. On editor mount, restore from last saved draft if exists. This requires only a debounce hook and a PATCH endpoint — low effort, high user value.

📄 components/blog/editor.tsx · app/api/posts/[id]/route.ts
Low PMB Contact Lists Are Stored as Plain Arrays — No Deduplication

PMB media contact lists are stored as JSON arrays with no deduplication check on insert. If a user imports the same CSV twice or manually adds a duplicate email, the same address receives two copies of every blast. This creates a poor recipient experience and counts double toward Resend usage quotas.

Recommended Fix

Normalise contact storage: move to a pmb_contacts table with a unique constraint on (list_id, email). On import, use INSERT ... ON CONFLICT DO NOTHING to deduplicate automatically. Show deduplication counts in the import UI (“3 duplicates skipped”).
