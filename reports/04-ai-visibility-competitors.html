Issues Found

Critical Citation Cron Runs Sequentially — Vercel Timeout Risk at Scale

The citation-checker cron runs all engine queries sequentially in a single serverless function. At 10+ monitors x 5 engines that is 50+ serial HTTP calls. Vercel cron functions have a 10–60 second execution limit depending on plan tier. With even moderate account growth, this will silently timeout and skip checks with no error logged or user notified.

Recommended Fix

Introduce a queue-based approach: cron enqueues jobs into a citation_check_queue table, a separate worker route processes N checks per invocation. Alternatively use Promise.allSettled for parallel engine calls per monitor (max 5 concurrent). Add execution time tracking — log when cron exits before completing all monitors.

📄 app/api/cron/citation-checker/route.ts · lib/services/citation.ts
Critical No Rate Limiting on Manual Citation Check Endpoint

When a user manually triggers citation checks, there is no rate limiting at the API layer. A user can call the endpoint repeatedly and exhaust the platform’s shared OpenAI / Gemini / Perplexity API quota in minutes. Each citation check makes up to 5 external API calls. There is no per-user daily check quota enforced server-side.

Recommended Fix

Add a rate limiter: max 20 manual checks per user per day. Track in citation_usage table (user_id, date, count). Return HTTP 429 with a clear message and quota-reset time. Show remaining quota in the UI. Paid plans get higher limits. Reuse the in-memory rate limiter already used in monitor routes.

📄 app/api/citation/check/route.ts
High Competitor Scraper Has No SSRF Protection

The competitor monitoring feature accepts any URL from the user and makes a server-side HTTP request without validating the target IP. If a user enters an internal AWS metadata URL (169.254.169.254) or a private IP range, the server will attempt to fetch it. This is an SSRF vulnerability that could expose internal Vercel or AWS infrastructure details.

Recommended Fix

Validate competitor URLs before fetching: block private IP ranges (10.x, 172.16-31.x, 192.168.x, 127.x, 169.254.x, ::1). Resolve DNS and check the resolved IP. Restrict to ports 80 and 443. Reject non-HTTPS schemes. The HTTP monitor checker already has SSRF protection in lib/utils/ssrf-guard.ts — reuse that exact validator.

📄 lib/services/competitor-analyser.ts · lib/utils/ssrf-guard.ts
High Competitor Body Truncated at 8KB of Raw HTML — Misses Key Content

The competitor scraper fetches the competitor homepage and truncates to 8KB of raw HTML before passing to Claude. Modern marketing pages with hero sections, feature lists, and pricing tables easily exceed 8KB of HTML. The AI analysis is therefore scoring based on nav bars and script tags rather than actual content. Gap analysis results are unreliable.

Recommended Fix

Strip HTML tags first (extract visible text only using a regex tag stripper or DOM parser), then truncate the plain text to 32KB. This gives Claude access to 5-10x more meaningful content. Also cache the extracted text in competitor_snapshots table to enable re-analysis without re-fetching.

📄 lib/services/competitor-analyser.ts
Medium llms.txt Fetch Not Verified After Generation

Uptrue generates and serves llms.txt but has no mechanism to verify AI crawlers are actually fetching it. The dashboard shows “llms.txt active” once the file is generated. Users may assume AI engines are indexing their brand when they are not. Without verification, the llms.txt feature provides false confidence.

Recommended Fix

Add a weekly self-fetch verification cron: Uptrue fetches its own /[domain]/llms.txt endpoint and records HTTP status and response time in a llms_txt_checks table. Show last-verified timestamp and status in the dashboard. If verification fails (404, timeout), surface a warning banner to the user.

📄 app/api/cron/ · app/[domain]/llms.txt/route.ts
Medium Citation Analysis Prompt Not Versioned — Historical Scores Incomparable

The Claude prompt for analysing AI engine responses is hardcoded inline in the service function. If the prompt is changed (even to fix a bug), historical scores become incomparable. A score of 72 in March vs 72 in April may use completely different evaluation criteria. Trend charts can mislead users.

Recommended Fix

Move prompts to a prompt_versions table with a version_id and created_at. Record prompt_version_id on every citation_checks row. When rendering trend charts, flag cross-version comparisons with a tooltip. This also enables A/B testing of prompt improvements without disrupting live score history.

📄 lib/services/citation.ts · lib/prompts/
Medium No Fallback or Retry When AI Engine API Returns Error

When an external AI engine API returns an error or rate-limit response, the citation check fails silently. The check is marked failed in the DB but no retry is attempted and users are not informed their scheduled check did not run. Over time this creates silent gaps in trend data that users interpret as low scores.

Recommended Fix

Implement exponential backoff with 3 retries for transient errors (5xx, 429). Log failure reason distinctly: status 'api_error' vs 'no_mention' vs 'timeout'. Surface failed checks as gaps (not zeros) in trend charts. Send user notification email after 3 consecutive failed checks for the same monitor.

📄 lib/services/citation.ts
Low Health Score Formula Hardcoded — Not Configurable or Explained to Users

The AI visibility health score uses a weighted formula with hardcoded constants. Users cannot see how their score is computed and the team cannot adjust weights for different industries (e.g., e-commerce vs SaaS) without a code deploy. This reduces trust in the metric and limits experimentation.

Recommended Fix

Move score weights to a scoring_config JSON or admin table. Add a “How is this score calculated?” tooltip in the dashboard UI showing the current formula components. This builds user trust and enables A/B testing of scoring models to improve metric accuracy over time.

  • Add per-user rate limit (20/day) on manual citation check endpoint
  • Fix body extraction: strip HTML before 8KB truncation in competitor scraper
  • Distinguish citation check failures from “not mentioned” in DB status field

Short-Term (1–2 Sprints)

  • Queue-based citation cron to avoid Vercel timeout at scale
  • llms.txt weekly self-verification cron with last-verified UI indicator
  • Version citation analysis prompts, store version ID per check row
  • Exponential backoff with 3 retries for AI engine API errors
  • Weekly citation digest email via Resend template

Architecture

  • Dedicated citation_check_queue table with worker route — decouple scheduling from execution
  • Cache competitor extracted text in competitor_snapshots for re-analysis without re-fetch
  • Adapter pattern for AI engines: one interface, one implementation per engine — add Grok + Meta AI easily
  • Citation trend anomaly detection: flag unusual drops before users notice them
  • Export citation history as CSV + PDF for enterprise reporting
