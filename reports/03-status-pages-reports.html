Issues Found

CRITICAL — Security
deleteReport() has no org_id check — any user can delete any report
deleteReportAction calls deleteReport(id) without verifying the report belongs to the requesting org. Any authenticated user who knows a report ID can delete another org's report. Classic privilege escalation.
✦ Fix: Add org_id to the delete query: .delete().eq('id', id).eq('org_id', user.org_id). Verify the returned count > 0 (if 0, the report didn't belong to this org).
lib/db/reports.ts · deleteReport() + app/(dashboard)/dashboard/reports/actions.ts
/dashboard/reports/new has no authentication check
The report generation page component does not call getCurrentUser() or redirect('/login'). Any visitor who navigates to /dashboard/reports/new sees the full report generation form.
✦ Fix: Add const user = await getCurrentUser(); if (!user) redirect('/login'); at the top of the page component. Same pattern as all other dashboard pages.
app/(dashboard)/dashboard/reports/new/page.tsx
HIGH — Missing Features
Webhook delivery job for status page subscribers does not exist
Slack/Teams webhooks are stored in DB but no background job, cron, or event handler sends them when monitor status changes. Webhook subscribers receive zero notifications.
✦ Fix: Add a notifyStatusPageSubscribers(monitorId, newStatus, incident) function. Call it from the check runner when monitor status changes. Decode webhook subscribers from the webhook:type:url email format and POST to each URL. Better long-term: add a dedicated webhook_subscriptions table.
lib/db/status-pages.ts · subscribeWebhookToStatusPage()
Email subscriber confirmation email never sent
The subscribe endpoint generates a confirmation_token and stores it, but never sends a confirmation email to the subscriber. All subscribers are stored in an unconfirmed state permanently.
✦ Fix: After subscribeToStatusPage() succeeds, call sendEmail() with a confirmation link: /status/{slug}/confirm?token={confirmation_token}. Add a confirm endpoint that sets confirmed=true.
AI report limit not enforced — unlimited generation on all plans
checkAiReportLimit() always returns { allowed: true }. generateReportAction doesn't even call it. All users can generate unlimited AI reports regardless of their plan.
✦ Fix: Implement the monthly report COUNT query. Call checkAiReportLimit(orgId) at the start of generateReportAction(). Return 403 with plan upgrade suggestion if limit exceeded.
lib/utils/plan-limits.ts · line 201 + app/(dashboard)/dashboard/reports/actions.ts
MEDIUM — Design Issues
Webhooks stored as encoded email string — design smell
Slack/Teams webhooks stored as webhook:slack:https://hooks.slack.com/… in the email column of status_page_subscribers. Makes querying, filtering, and managing webhooks extremely fragile. One schema change could break all webhook lookups.
✦ Fix: Create a status_page_webhooks table (status_page_id, webhook_url, webhook_type, created_at). Migrate existing encoded entries. Update subscribe/unsubscribe endpoints.
lib/db/status-pages.ts · subscribeWebhookToStatusPage()
Public status page has no caching — every request hits DB during outages
export const dynamic = 'force-dynamic' means every visit to /status/{slug} makes multiple Supabase queries. During an outage, this page receives the most traffic at the worst possible time.
✦ Fix: Use Next.js revalidate (ISR) with a 30-second TTL. The page data changes infrequently — even 30-second caching reduces DB load by 95% during high-traffic outage events.
app/status/[slug]/page.tsx
Report generation has no pagination — OOM risk on large orgs
generateReport() fetches all check_results for the period with no limit. An org with 100 monitors over a 90-day period could produce 100 × 90 × 24 × 60 = millions of rows, exhausting memory.
✦ Fix: Add a hard limit (e.g. 50,000 rows) with a warning in the report if truncated. Or use DB-side aggregation (GROUP BY monitor_id, DATE) to pre-aggregate before returning raw rows.
lib/services/reports.ts · generateReport()
Change digest silently truncates at 200 events
High-volume change-detection monitors produce more than 200 events but only 200 are included in the report. The user has no indication that the report is incomplete.
✦ Fix: Return the total event count alongside the 200-item slice. Show a banner in the ReportViewer: "Showing 200 of 1,453 change events. Export CSV for full data."
reportType not a queryable DB column — stored inside JSON only
Report type is stored only inside the data JSON blob. Cannot filter or sort reports by type in the DB layer without full-table scans.
✦ Fix: Add a report_type text column to the reports table. Populate on insert. Index it. This enables "show me all uptime reports for the last 3 months" queries.
apexDomain() fails on IP-address monitors
The domain grouping function splits on dots and assumes DNS names. Monitors with IP targets (e.g. 192.168.1.1) produce invalid domain keys in site-health and security-audit reports.
✦ Fix: Detect IP address format (regex or URL parse) before calling apexDomain(). Return the IP as-is as the group key for IP-targeted monitors.
lib/services/reports.ts · apexDomain()
LOW — UX / Missing Features
No subscriber management UI — cannot view or remove subscribers per status page
✦ Add a subscribers tab on the status page detail page. List email + confirmed status. Allow admin to remove individual subscribers.
Reports list silently truncates at 20 — no pagination or load-more
✦ Add pagination params to getReportsForOrg(). Add a "Load more" button or infinite scroll in the reports table.
No reports REST API — reports are UI-only, no integration path
✦ Add GET /api/v1/reports (list) and GET /api/v1/reports/{id} (single) with API key auth. Enables third-party integrations and scheduled reporting.
Custom domain verification UI missing — DB fields exist but not exposed
✦ Add a "Custom Domain" tab to the status page edit form. Show the DNS TXT verification token. Add a "Verify DNS" button that calls a verification endpoint.
New monitors show 100% uptime on status pages before first check
✦ Return null from getUptimePercentage() when no data. Render "Checking..." instead of 100%.
Unsubscribe endpoint returns HTML — inconsistent with JSON subscribe response
✦ Accept Accept: application/json header and return JSON for API consumers. Keep HTML for browser unsubscribe links.

Suggestions & Improvements

Immediate — Security

Add org_id check to deleteReport() — one-line fix, prevents privilege escalation
Add authentication to /dashboard/reports/new — missing getCurrentUser() guard
Send email confirmation to status page subscribers after subscribe API call

Short-Term — Functionality

Build webhook delivery job — notifyStatusPageSubscribers() called from check runner on status change
Create dedicated status_page_webhooks table — retire the encoded email hack
Add ISR caching (revalidate: 30) to /status/{slug} — critical for performance during outages
Implement AI report monthly limit COUNT query — the TODO has been open long enough

Architecture

Add report_type column to reports table — enables filtering/sorting without JSON parsing
Add Reports REST API (/api/v1/reports) — enables integrations, scheduled reporting, third-party tools
Paginate generateReport() check_results fetch — prevent OOM on large orgs with long periods
Add scheduled monthly report cron — plans mention "monthly" type but no auto-generation exists
